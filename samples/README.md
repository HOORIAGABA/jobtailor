# samples/

Resumes to run the pipeline against.

```bash
python scripts/parse_resume.py samples/ --text-only   # extraction only, no API calls
python scripts/parse_resume.py samples/               # full S0, one call per file
```

## What is committed

Three synthetic resumes, regenerated by `python scripts/make_samples.py`. Each
one exists because it breaks something:

| File | Why it is here |
|---|---|
| `two_column.pdf` | A sidebar layout. Every naive extractor interleaves it, and the parser then sees a skills line wedged between a job title and its bullets. |
| `single_column.pdf` | The easy case, as a control. If this ever fails, the bug is not in the layout code. |
| `table_layout.docx` | An invisible two-column table — how a large share of Word resume templates are built. `document.paragraphs` returns almost nothing for these, *without raising*. |

They contain no real personal data, so a fresh clone can run the whole pipeline
without anybody's actual CV.

## Your own resumes

Drop them in here. `.gitignore` in this folder ignores everything except the
three files above, so anything you add stays local.

That is deliberate, and it is the second time this has come up: v1 kept a
folder of real resume PDFs at the repo root that `.gitignore` did not cover,
one `git add -A` away from being public. A resume is a name, an address, a
phone number and an employment history — the default has to be *not committed*.

The same applies to `runs/`, which holds the full extracted text of whatever
was parsed. Also ignored, for the same reason.

## What a run writes

```
runs/2026-09-24T14-32-10_your_resume/
  00_extract.txt      S0.1 — the text, in reading order
  01_parse.json       S0.2 — what the model made of it
  02_coverage.json    S0.2v — what it dropped or invented
  03_normalize.json   S0.3 — ids, classification, grounding corpus
  manifest.json       input hash, model, token cost, timings
```

Change a prompt, re-run, and `diff` the two folders. That turns "it feels
worse" into a specific line that changed.
